# ComfyUI 节点接入规格

## 1. 背景与目标

当前项目支持文本、图片、视频、音频、配置和插件节点，但还不能直接调用本机或局域网中的 ComfyUI 工作流。

本功能参考 `hero8152/Infinite-Canvas` 的使用方式，在现有纯前端画布架构中增加完整的 ComfyUI 接入能力：

- 配置并测试一个 ComfyUI 实例。
- 导入、配置、测试和管理 ComfyUI API Format 工作流。
- 在画布中创建 ComfyUI 节点，消费上游文本与媒体资源。
- 提供文生图、增强、编辑和自定义四种节点模式。
- 通过 ComfyUI 标准 HTTP API 上传素材、提交工作流并查询结果。
- 解析图片、视频、音频和文本输出，保存到浏览器本地后创建普通画布节点。
- 保存 `prompt_id`，支持页面刷新后的任务恢复查询。

浏览器继续直接请求外部服务，不新增项目后端。遇到跨域限制时复用项目已有的本地代理。

## 2. 范围

### 2.1 包含

- 单个 ComfyUI 实例。
- ComfyUI API Format 工作流。
- 工作流导入、复制、编辑、删除和测试。
- 工作流字段自动识别与人工修正。
- 文生图、增强、编辑三个预设模式的工作流绑定。
- 自定义工作流模式。
- 上游画布资源自动映射。
- ComfyUI 标准 HTTP API 调用。
- 图片、视频、音频和文本输入与输出。
- 本地产物持久化。
- 节点运行状态、错误诊断和任务恢复。
- 中英文界面文案与用户文档。

### 2.2 不包含

- 多实例负载均衡、自动调度或故障转移。
- RunningHub、ModelScope 或其他云端工作流平台。
- ComfyUI、模型或自定义节点的安装与下载。
- 随项目附带模型专用工作流。
- ComfyUI 原生节点图的可视化编辑。
- WebSocket 实时预览帧。
- 自动调用 `/interrupt` 或删除 ComfyUI 队列任务。
- 云端保存 ComfyUI 地址、工作流或执行历史。

## 3. 用户流程

### 3.1 首次配置

1. 用户进入“配置 → ComfyUI”。
2. 输入带协议的 ComfyUI 地址，例如 `http://127.0.0.1:8188`。
3. 点击“测试连接”，前端请求 `/system_stats`。
4. 成功时展示实例可用状态和可获取的设备摘要。
5. 若请求被跨域策略阻止，提示为 ComfyUI 开启 CORS，或启用项目已有的本地代理。
6. 地址通过格式校验后保存到浏览器本地。

### 3.2 导入工作流

1. 用户在 ComfyUI 中导出 API Format JSON。
2. 在 ComfyUI 工作流管理区选择 JSON 文件。
3. 系统验证格式并扫描可配置输入。
4. 系统结合 `/object_info` 和本地规则推断字段类型。
5. 用户选择需要暴露的字段，调整名称、类型、顺序、默认值和预设角色。
6. 用户在测试区填写参数、上传媒体并执行工作流。
7. 测试结果正确后保存工作流配置。

### 3.3 在画布中运行

1. 用户创建 ComfyUI 节点。
2. 选择文生图、增强、编辑或自定义模式及对应工作流。
3. 将文本、图片、视频、音频或资源分组连接到节点。
4. 节点面板展示实际输入映射和剩余参数。
5. 点击运行后，节点依次显示上传、排队、运行和处理结果状态。
6. 完成后在节点右侧创建普通资源节点并自动连线。
7. 下游功能继续使用这些普通资源节点，不依赖 ComfyUI 节点充当资源。

## 4. ComfyUI 配置

### 4.1 数据结构

```ts
type ComfyUiConfig = {
    baseUrl: string;
    presetWorkflowIds: {
        text: string;
        enhance: string;
        edit: string;
    };
};
```

约束：

- `baseUrl` 必须是带协议的 HTTP 或 HTTPS 地址。
- 保存前去除末尾的 `/`，不自动增加 `/api` 前缀。
- 地址为空或格式非法时禁止测试和保存。
- 首版只保存一个实例。
- 配置只保存在浏览器本地。

### 4.2 连接测试

请求：

```http
GET {baseUrl}/system_stats
```

成功条件：

- HTTP 状态为 2xx。
- 响应可以解析为 JSON。
- 不要求特定操作系统、GPU 品牌或显存大小。

错误提示需要区分地址非法、本地代理不可用、跨域失败、连接被拒绝、非 2xx 响应和无效 JSON，不能统一显示为“连接失败”。

## 5. 工作流数据模型与存储

```ts
type ComfyApiNode = {
    class_type: string;
    inputs: Record<string, unknown>;
    _meta?: { title?: string };
};

type ComfyWorkflowFieldType =
    | "text"
    | "textarea"
    | "number"
    | "slider"
    | "dropdown"
    | "boolean"
    | "image"
    | "video"
    | "audio";

type ComfyPresetRole =
    | "prompt"
    | "image"
    | "strength"
    | "width"
    | "height"
    | "seed";

type ComfyWorkflowField = {
    id: string;
    nodeId: string;
    inputKey: string;
    nodeTitle: string;
    label: string;
    type: ComfyWorkflowFieldType;
    enabled: boolean;
    order: number;
    defaultValue?: unknown;
    options?: Array<string | number>;
    min?: number;
    max?: number;
    step?: number;
    randomize?: boolean;
    presetRole?: ComfyPresetRole;
};

type ComfyWorkflow = {
    id: string;
    name: string;
    description: string;
    workflow: Record<string, ComfyApiNode>;
    fields: ComfyWorkflowField[];
    createdAt: string;
    updatedAt: string;
};
```

工作流及其字段配置使用独立的 localforage store 保存，不使用 `localStorage`。原始工作流对象保存后视为不可变模板，每次执行都从深拷贝生成请求体。

## 6. 工作流导入与校验

### 6.1 支持格式

只支持以节点 ID 为键、节点包含 `class_type` 和 `inputs` 的 ComfyUI API Format：

```json
{
  "3": {
    "class_type": "KSampler",
    "inputs": {
      "seed": 123,
      "steps": 20
    }
  }
}
```

### 6.2 拒绝条件

以下情况拒绝导入：

- 根值不是普通对象或工作流为空。
- 任一节点值不是对象。
- 没有任何节点包含 `class_type`。
- JSON 解析失败。
- 文件使用包含 `nodes`、`links` 等字段的普通 UI 工作流结构。

普通 UI 工作流应提示：

> 当前文件不是 ComfyUI API 格式。请在 ComfyUI 中使用“Export API”或“Save (API Format)”重新导出。

### 6.3 字段扫描

只把 literal input 作为候选字段。形如 `['12', 0]` 的二元数组视为节点连线，不允许暴露或覆盖。

每个候选字段需要记录节点 ID、节点标题、`class_type`、输入键名、原始默认值和推断类型。

### 6.4 类型推断

导入时优先请求：

```http
GET {baseUrl}/object_info
```

当对象信息可用时：

- 枚举输入映射为 `dropdown`。
- 带最小值、最大值和步长的数字映射为 `slider` 或 `number`。
- 布尔输入映射为 `boolean`。
- 图片、视频、音频类型映射为对应媒体类型。

对象信息不可用时使用以下规则：

- `text`、`prompt`、`positive`、`negative` → `textarea`。
- `seed`、`noise_seed` → `number`，默认允许随机。
- `steps`、`cfg`、`denoise`、`strength` → `slider`。
- `width`、`height`、`batch_size` → `number`。
- `image`、`images`、`mask` → `image`。
- 名称包含 `video` → `video`。
- 名称包含 `audio` 或 `sound` → `audio`。
- 布尔值 → `boolean`；数字 → `number`；其他字符串 → `text`。

所有推断结果都允许人工修改。

## 7. 配置页与工作流管理

配置页新增“ComfyUI”标签，包含实例区和工作流区。

实例区提供地址输入、连接测试、保存状态、本地代理说明和最近一次测试结果。

工作流列表显示名称、已暴露字段数量、媒体输入类型、预设绑定和更新时间，并提供导入、编辑、复制、测试和删除操作。

工作流编辑器支持：

- 修改名称和描述。
- 搜索节点标题、节点类型和输入字段。
- 启用或关闭字段。
- 修改字段名称与控件类型。
- 拖动调整字段顺序。
- 设置默认值、数字范围、步长、下拉选项和随机行为。
- 设置预设角色。
- 保存配置或进入测试区。

同一工作流中，`prompt`、`strength`、`width`、`height`、`seed` 角色各最多一个；`image` 角色允许多个，并按字段顺序映射。

删除工作流前需要检查画布引用并提示影响。确认删除后，已有节点保留原工作流 ID并显示“工作流不存在”，不得静默切换到其他工作流。

## 8. 工作流测试区

测试区根据启用字段动态生成文本、多行文本、数字、滑块、下拉、开关以及图片、视频、音频上传控件。

测试运行复用正式 ComfyUI 请求流程，但不创建画布节点。结果区支持图片网格、视频播放器、音频播放器、文本结果、原始错误详情、`prompt_id` 和重新查询操作。

## 9. 画布节点

新增内置节点类型：

```ts
CanvasNodeType.ComfyUI = "comfyui";
```

节点默认行为：

- 标题为 `ComfyUI`。
- 使用当前画布主题和现有配置面板视觉风格。
- 接收文本、图片、视频、音频和资源分组。
- 节点自身不声明为资源；正式产物由新建的普通资源节点承载。
- 点击节点打开底部配置面板。
- 节点内容区只展示模式、工作流、输入摘要和运行状态。

节点元数据新增：

```ts
type ComfyNodeMetadata = {
    comfyMode: "text" | "enhance" | "edit" | "custom";
    comfyWorkflowId?: string;
    comfyValues?: Record<string, unknown>;
    comfyRandomEnabled?: Record<string, boolean>;
    comfyRunStatus?: "idle" | "uploading" | "queued" | "running" | "processing" | "success" | "error";
    comfyPromptId?: string;
    comfyError?: string;
    comfyOutputNodeIds?: string[];
};
```

这些字段随画布项目持久化。运行中的节点不得被现有“中断生成重置”逻辑直接丢弃 `prompt_id`。

## 10. 节点模式

### 10.1 文生图

绑定的工作流必须有一个 `prompt` 角色；可选 `width`、`height` 和 `seed`。上游文本合并后覆盖提示词角色，其余字段由节点面板提供。

### 10.2 增强

绑定的工作流必须有至少一个 `image` 角色；可选 `strength` 和 `seed`。第一个上游图片映射到图片角色，没有图片时禁止运行。

### 10.3 编辑

绑定的工作流必须有一个 `prompt` 角色和一个或多个 `image` 角色。上游图片按顺序映射，上游文本合并后填入提示词角色。

### 10.4 自定义

用户可选择任意已导入工作流：

- 上游文本存在时，按顺序填充启用的文本字段；没有上游文本时使用节点保存值。
- 图片、视频、音频分别按类型和字段顺序映射。
- 非媒体字段使用节点保存值。
- 未启用字段保持原始工作流值。
- 已启用的媒体字段缺少对应输入时禁止运行并指出字段名称。

三个预设模式只提供交互框架和角色映射，不随项目附带参考仓库中的模型专用工作流。

## 11. 输入顺序与映射预览

当前画布连接没有端口级字段标识，首版使用稳定顺序：

1. 目标字段按 `order` 排序。
2. 上游节点按画布连接数组顺序读取。
3. 分组节点内部按项目节点顺序展开。
4. 同类型资源依次映射，不在不同媒体类型之间混排。

节点面板必须展示实际映射预览，例如：

```text
图片 1 ← 产品原图
图片 2 ← 风格参考图
提示词 ← 文本节点 1 + 文本节点 2
```

用户通过调整连接顺序或工作流字段顺序改变映射。

## 12. 请求流程

### 12.1 媒体上传

每个媒体输入都需要从 `storageKey` 或当前 URL 读取 Blob，生成不会冲突的文件名，并上传到：

```http
POST {baseUrl}/upload/image
Content-Type: multipart/form-data
```

表单字段：

```text
image=<Blob>
type=input
overwrite=false
```

使用返回的 `name`、`subfolder` 和 `type` 覆盖工作流对应输入。图片、视频和音频都进入 ComfyUI input 目录，由具体工作流节点负责读取。

### 12.2 参数覆盖

提交前深拷贝原始工作流，只允许修改已配置字段对应的 `workflow[nodeId].inputs[inputKey]`。

不得修改原始模板、覆盖不存在的节点、覆盖节点连线输入，或把画布私有字段写入工作流。

### 12.3 提交

```http
POST {baseUrl}/prompt
Content-Type: application/json
```

请求体：

```json
{
  "prompt": {},
  "client_id": "infinite-canvas-<uuid>"
}
```

保存响应中的 `prompt_id`。若响应包含 `node_errors`，立即进入错误状态，并优先展示节点名称、节点类型、输入字段和 ComfyUI 原始错误。

### 12.4 状态轮询与恢复

按「配置 → ComfyUI → 实例」中设置的轮询间隔请求（预设 1 / 3 / 5 / 10 秒或自定义秒数，最小 1 秒、无上限，默认 3 秒）：

```http
GET {baseUrl}/history/{prompt_id}
```

- 不设置任务总超时。
- 不调用 `/interrupt`，不删除远端队列。
- 历史中暂时没有该 ID时继续等待。
- 成功终态进入输出处理；失败终态展示执行错误。
- 页面关闭或组件卸载只停止当前浏览器轮询，不影响远端任务。
- 页面重新打开后，存在 `prompt_id` 且没有终态的节点自动恢复查询。
- ComfyUI 历史已被清理时提示无法恢复，但保留 `prompt_id` 供诊断。

## 13. 输出解析

从历史记录的 `outputs` 中扫描媒体文件对象：

```ts
type ComfyOutputFile = {
    filename: string;
    subfolder?: string;
    type?: "input" | "output" | "temp";
};
```

下载地址：

```http
GET {baseUrl}/view?filename=...&subfolder=...&type=...
```

根据响应 MIME、扩展名和输出字段名判断图片、视频或音频。

文本输出识别 `text`、`texts`、`string`、`strings`、`caption`、`captions`、`prompt`、`prompts`，并支持字符串、数组以及包含 `text` 或 `value` 的对象。

当存在正式输出时，过滤 `PreviewImage`、图片比较器、ShowText、ShowAnything、Note、Debug、数学表达式和中间状态文本。若完全没有正式输出，允许使用可识别的 Preview 输出作为结果。

输出使用“输出节点 ID + filename + subfolder + type”去重，同一个文件不得重复创建画布节点。

## 14. 结果持久化与画布落点

下载后的图片使用现有图片存储服务，视频和音频使用现有文件存储服务，文本直接写入文本节点元数据。

节点创建规则：

- 同一任务的多张图片创建一个批量图片节点。
- 同一任务的多个文本结果创建一个批量文本节点。
- 每个视频创建一个视频节点。
- 每个音频创建一个音频节点。
- 结果节点排列在 ComfyUI 节点右侧，并与其建立连接。
- 每次运行创建新的结果节点，不覆盖旧产物。
- `comfyOutputNodeIds` 只记录最近一次运行创建的节点。

产物保存到本地后，不再依赖 ComfyUI output 目录长期保留文件。

## 15. 状态与交互

节点状态为：

```text
idle → uploading → queued → running → processing → success | error
```

- `uploading`：正在上传输入素材。
- `queued`：已获得 `prompt_id`，等待执行。
- `running`：历史或队列状态表明任务正在执行。
- `processing`：正在下载并保存结果。
- `success`：展示本次产物数量。
- `error`：展示短错误，并允许展开详情。

运行期间禁用重复提交，但不阻塞其他画布操作；不显示无法从 API 得出的虚假百分比。

错误后提供重试、复制错误详情、使用原 `prompt_id` 重新查询和打开 ComfyUI 配置。重试创建新的 `prompt_id`，重新查询不得重复提交工作流。

## 16. 错误处理

必须覆盖并区分：

- ComfyUI 地址未配置或格式非法。
- 本地代理未启动、跨域失败或连接被拒绝。
- 工作流不存在、已删除或格式损坏。
- 工作流字段引用的节点或输入不存在。
- 上游媒体数量不足。
- 本地媒体读取、上传或持久化失败。
- `/prompt` 校验失败。
- 自定义节点或模型缺失。
- ComfyUI 执行异常。
- 历史记录缺失或已清理。
- 工作流成功但没有可识别输出。
- 输出下载失败。

不得把以上情况统一显示为“生成失败”。能够取得 ComfyUI 原始错误时，必须保留节点标题、节点类型和字段信息。

## 17. 配置导出与同步

应用配置导出包含 ComfyUI 地址、预设绑定、工作流定义和字段配置，但不包含 Blob URL、运行中临时状态、媒体二进制或完整历史响应。

WebDAV 应用数据同步可以同步工作流定义和配置；媒体文件继续沿用现有媒体同步机制。产品文档必须明确这些数据首先保存在浏览器本地，不能表述为已提供云端 ComfyUI 工作流服务。

## 18. 测试要求

### 18.1 单元测试

- API Format 识别与 UI 工作流拒绝。
- literal input 与节点连线区分。
- 字段类型推断及 `/object_info` 合并。
- 预设角色唯一性。
- 上游文本与媒体顺序映射。
- 参数类型转换和随机 seed。
- 深拷贝和受限字段覆盖。
- 输出类型识别、调试输出过滤和去重。

### 18.2 API 服务测试

使用 mock fetch 覆盖连接测试、媒体上传、提交成功、`node_errors`、历史等待/成功/失败、混合类型输出、`/view` 下载失败和本地代理 URL 包装。

### 18.3 状态与持久化测试

- 工作流保存、更新、复制和删除。
- 节点参数刷新后保留。
- `prompt_id` 刷新后恢复轮询。
- 已完成任务不会重复创建结果。
- 工作流删除后已有节点显示缺失状态。
- ComfyUI 清理输出后，本地产物仍可读取。

### 18.4 真实验收

1. 测试一个真实 ComfyUI 实例。
2. 导入 API Format 文生图工作流。
3. 暴露提示词、seed、宽度和高度。
4. 在工作流测试区成功生成图片。
5. 在画布创建 ComfyUI 节点并连接文本节点。
6. 运行后自动创建图片结果节点。
7. 刷新页面后图片仍可查看。
8. 再次运行后旧结果保留，新结果单独创建。
9. 使用工作流分别验证视频、音频和文本输出。

## 20. 完成标准

满足以下条件才视为 ComfyUI 接入完成：

- 用户无需手工修改 JSON 即可导入和配置 API 工作流。
- ComfyUI 节点能正确消费画布文本、图片、视频和音频。
- 参数覆盖不会修改或破坏原始工作流模板。
- 长任务能持续等待，并能在刷新后通过 `prompt_id` 恢复。
- 图片、视频、音频和文本结果能转换为普通画布节点。
- 产物已保存到浏览器本地，不依赖 ComfyUI 输出目录长期存在。
- 所有主要失败场景都有明确、可诊断的错误信息。
