# 生成任务系统通知验收

- 桌面端由 Electron 主进程发送原生通知，仅接受受信任应用主页面的固定 IPC；点击恢复、显示并聚焦窗口，通过固定事件传递结构化任务目标，不加载任意 URL。
- 工作台在生成记录保存后通知，图像批量一次汇总，视频 pending 记录不通知；ComfyUI 多视频输出汇总一次。图像重试失败新增失败记录，保证通知可打开对应错误。
- 内置画布图片、文本、视频、音频、蒙版与视角生成、重试和视频恢复均在实际终态通知；ComfyUI 运行、恢复、再次查询按服务 prompt ID 去重。手动取消不发失败通知；导入和历史加载不产生历史通知。
- `node --test desktop/tests/notifications.test.mjs desktop/tests/project-creation.test.mjs`：6 项通过。通知覆盖成功/失败目标、去重、窗口恢复/显示/聚焦、无效目标拒绝、不支持系统、失败后可重试和已销毁窗口。
- `verification/notification-native.cjs` 使用独立 Electron 进程加载实际通知模块；系统通知收到 show 事件后模拟 click，确认恢复/显示/聚焦与目标转发。结果见 `notification-native-result.json`，supported/shown/clicked 均为 true。这不是手动点击系统通知中心的验收。
- 隔离浏览器使用内存桌面桥和模拟图片响应，实际点击生成，验证成功/失败通知、跨页面点击后恢复对应记录、图片/失败原因显示和 query 消费。批量部分失败文案返回“2 项成功，1 项失败”。
- 隔离创作页含离屏目标节点 (2000,1600)，通知导航后目标实际可见且选中，跨页面和同页重复点击均通过。修复定位依赖动画帧导致 query 已消费但视口未移动的问题，深链直接设置定位视口。
- 预览服务无编译错误；控制台仍有未启动本地 Agent 的连接拒绝。未调用真实模型或 GPU，未构建、重启或修改用户桌面实例；真实生成全流程、系统通知中心手动点击与其他平台尚待验收。
